# 本地验证记录

日期：2026-10-19。范围为本地单应用实例，不包含真实支付、生产部署或 RocketMQ Broker 故障验证。

## 自动化回归

使用 JDK 17.0.20.1、Maven 3.9.16、真实 Redis 5.0.14、H2 2.1.214 MySQL 模式。

执行 `./scripts/test.ps1`：脚本启动随机独立端口 Redis，结束后关闭该实例；未连接或清空用户现有默认 Redis。20 项测试通过，无失败。

| 测试类 | 数量 | 重点 |
| --- | ---: | --- |
| CacheRegressionTest | 6 | 缺失回源、负缓存、逻辑刷新、本地命中、失效阻止旧回填、L1 并发填充与失效 |
| CacheInvalidationRegressionTest | 3 | 回滚不删缓存、提交后失效、Redis 故障保留任务并可重试 |
| OrderLifecycleRegressionTest | 9 | 重复消息、数据库回滚、失败任务保留、付款保护、关单释放、并发预占、活动时间、失败释放重试、退款待办幂等 |
| RateLimitRegressionTest | 1 | 同毫秒请求独立计数、窗口外记录清除 |
| DelayLevelTest | 1 | 默认延迟档位选择和提前检查的剩余时间安排 |

缓存缺失及重建误删数据的问题先由回归复现：3 项失败，修正后通过。独立代码检查发现 L1 旧值并发回填问题，增加可控线程交错测试，先复现 `expected new but was old`，再加入共享分段锁后通过。

原仓库的预热全表、生成 Token、批量 ID 等人工数据准备测试标记为 `manual`，不计入自动化结果。

## 实际应用冒烟

为避免修改已有 MySQL，使用独立 MySQL 8.0.40 数据目录和端口 13306；应用监听 127.0.0.1:18081；Redis 使用隔离测试实例的 DB 12。

导入基础 SQL 和一次性升级脚本。修正基础 SQL 中 MySQL 8 严格模式不接受的零日期默认值；没有放宽现有 MySQL 全局配置。

启动参数缩短为付款期 5 秒、扫描间隔 1 秒，以检查到期流程：

```powershell
./scripts/smoke-local.ps1 -BaseUrl http://127.0.0.1:18081 -RedisPort 16379 -RedisDatabase 12 -TimeoutSeconds 5
```

验证项目：

- 无预热时正常查询商铺，重复读取正常。
- 商铺更新后两层缓存失效，能读取提交的新值；脚本恢复原名称。
- 创建活动，Redis 初始化库存及活动时间。
- 请求返回预占订单号，后台创建数据库订单。
- 同一用户重复抢券被拒绝。
- Spring Task 自动关闭到期订单，归还 Redis 名额。
- 同用户取消后可重新抢券。
- 本地模拟付款成功后，定时扫描不关闭已支付订单。
- 原订单晚到支付只记录退款待办，不额外释放新订单占用的名额。

这是功能和一致性验证，不是 JMeter 性能测试；没有据此声称 QPS、平均响应时间或性能提升比例。

## 未验证／有意跳过

- 没有运行 RocketMQ Broker；该 profile 的生产者与监听器已编译，延迟档位选择有测试，真实投递和重试行为待实际 Broker 集成验证。
- local 的后台执行器不替代生产消息系统，Redis 待办不覆盖 Redis 数据丢失后的恢复。
- H2 用于快速事务回归，不能代替全部 MySQL 隔离级别／锁等待测试；另用真实 MySQL 做应用流程检查。
- 未实现真实支付验签、退款渠道、短信、权益核销、集群和自动全量对账。
